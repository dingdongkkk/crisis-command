# CC-08: replanning, approval and simulated delivery

- Author: Codex. Branch: `codex/cc-08-planning`, stacked on CC-07/CC-05.
- Status: ready for review, not independently reviewed or merged.

## Delivered

Background planning has one worker and a dirty marker with 250 ms coalescing. Solve/route work is outside SQLite's writer transaction. Publication checks the planning sequence again. Semantic comparison includes flags, facilities, routes and solver quality, not just assigned IDs. Approval validates session, proposal/version/sequence and required acknowledgements inside `BEGIN IMMEDIATE`. Stale or unacknowledged commands append rejection audit events.

Simulated delivery is an event transaction with session/plan/unit-revision fences. Superseding approvals cancel pending commands. Breakdowns increment the desired revision even before the first assignment was delivered, so repair cannot resurrect old queued work. Releases check the old assignment. Hospital pre-alerts are simulated and idempotent. Startup drains pending work; replay never dispatches.

Reports create intake facts, assessed incidents, human escalation and private report-text records transactionally. Canonical intake implementation remains Claude's unchanged module. Operator fact confirmation, pin/forbid/hold/bridge/provisional downgrade/revoke endpoints are available. World changes invalidate unavailable-unit and incompatible downgrade overrides.

Fixed two infrastructure issues found during integration: idempotency receipts are scoped to method/path/session/key without a conflicting unscoped event-index uniqueness rule; domain exceptions can cross Python transaction context managers without FrozenInstanceError.
