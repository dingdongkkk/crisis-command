Behaviour notes:

- Missing information is `unknown`; a negative needs words that say it ("not breathing", "saans nahi", "साँस नहीं"). "No fire" beats the contained "fire"; contradictory phrases become `conflict` → `CONFLICTING_FACTS`.
- Applicability follows 0002 (medical, accident, collapse, gas, flood, fire, ambiguous); information requests and breakdowns have no patient facts until danger appears. Road-condition words in a question ("is ORR flooded?") do not make it an emergency; a life threat, trapping, caller danger or fire does. Breakdowns upgrade on any danger (tyre → flood-stranded). Emergencies are never downgraded by later messages.
- Caller structured answers and operator confirmations override free-text findings; operator wins.
- `MODEL_UNAVAILABLE_CRITICAL_TEXT` fires when critical words ("poison", "seizure", "करंट"…) appear outside every evidence span and no model result is available — conservative by design in the default no-model demo.

## Known limitations

- The lexicon is a demonstration, not a clinical instrument; it covers the demo families and common phrasings only. Spelling variants and code-mixing beyond the listed forms will fall to `unknown` (safe direction) or be missed.
- The held-out set was written by the same agent as the lexicon, so 30/30 is not an independent measure; CC-11 should add an independently written set and measure recall/calibration.
- `people_count` takes the largest number mentioned; mixed counts (e.g. "2 injured, 40 residents") are approximate.
- Not wired to the API: `POST /reports`/answers need incident assessment (CC-05) to create incidents and needs. `IntakeSession` exposes everything the endpoint needs; report-text storage (separate revocable store, 0005) is not implemented yet.
- Session state is in memory; persistence comes with the API wiring.
