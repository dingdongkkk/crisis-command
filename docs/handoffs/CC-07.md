## Delivered

Owned paths: `backend/app/routing/`, `evals/fixtures/roads/`. Also: `backend/app/api/routes.py` (two read endpoints), `backend/app/contracts/commands.py` (+`RouteCandidate`, `RouteCandidates`), regenerated `contracts/` and `frontend/src/generated/`.

- **Road data (user-approved download):** OpenStreetMap roads for bbox 12.80,77.45,13.15,77.80 (motorway…tertiary, links, unclassified) via Overpass API, 16.5 MB raw → `evals/fixtures/roads/bengaluru-drive-v1.json.gz` (1.07 MB; 17,191 junction nodes, 22,710 edges; largest connected component; OSM one-way rules). ODbL-1.0, © OpenStreetMap contributors. `python -m app.routing.build_graph RAW OUT` rebuilds it byte-for-byte.
- **Router (`app/routing/router.py`):** A* on travel time (demo speeds per road class in `graph.py`, policy `routing-demo-2026.1` — not measured). Multi-candidate snapping onto road segments (nearest roads within +60 m, ≤ 400 m) so divided roads and ramps don't force loops. Access legs are straight, ≤ 400 m, at 12 km/h, and included in time/distance. Flood polygons with `closes_roads` close every edge they touch (vertex inside or boundary crossing).
- **No invented ETAs:** destination/origin in a closed zone, no open road within 400 m, or no path → `route_status: "unavailable"` + `unavailable_reason` (`DESTINATION_IN_CLOSED_FLOOD_ZONE`, `ORIGIN_IN_CLOSED_FLOOD_ZONE`, `…_NOT_NEAR_OPEN_ROAD`, `NO_OPEN_ROAD_PATH`) and no duration/geometry.
- **Cache:** routes memoised per (origin, destination, flood closure versions); blocked-edge sets per closure key. A new flood version always recomputes.
- **API:** `GET /routing/route?from_lon&from_lat&to_lon&to_lat` → `Route`; `GET /routing/candidates?incident_id=` → `RouteCandidates` (every unit's fastest road route to the incident under current closures; ready units by ETA, then units that cannot take tasks, then unavailable routes). Informational only — eligibility and allocation stay with the solver.
- **Recorder:** `python -m app.routing.record_candidates SNAPSHOT.json OUT.json` writes real router output for UI mocks and demos.

Measured on this laptop (Apple Silicon, Python 3.12): graph load 0.23 s; 28 routes with the Bellandur flood ≈ 0.1 s total; examples: B2 → school 72 s / 585 m; B1 → Silk Board 10 s / 49 m; F2 → Silk Board 1,091 s / 13.2 km (dry) and longer with the flood.

## Known limitations (remaining CC-07 scope)

- No OpenRouteService adapter (no API key); the fixture router is the only provider.
- Road classes: motorway→tertiary + unclassified only; residential streets are excluded, so last-metre access relies on ≤ 400 m straight access legs.
- Speeds are policy constants per road class; no traffic, turn costs or signal delays.
- Boats: water routing is not modelled — road routes into a flood zone are unavailable; boat eligibility/ETA for flood rescues needs a separate water-access rule.
- Facility reachability (incident → hospital/shelter onward routes) is supported by the router but not yet wired into plans (CC-05/CC-08).
- Tow-to-emergency upgrade inputs are not implemented here.
