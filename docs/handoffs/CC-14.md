# CC-14: Optional Laya and voice extensions

- Author: Claude (claude-opus-5-5)
- Branch and PR: `claude/cc-14-extensions` (#34), stacked on `claude/cc-13-demo` (#33). The PR body carries `Closes #14`.
- Status: **ready for review**: a negative result, recorded.

## Delivered so far

- `evals/laya/run_laya_eval.py`: an isolated harness scoring the rules, Laya alone, and the 0002-compliant `hybrid` mode on the 84 labelled triage cases. It reports unsafe downgrades, missed and false danger, category accuracy, calibration (Brier, ECE) and CPU latency.
- `docs/experiments/CC-14-laya.md`: the pinned checkpoint and licence, the method, and adoption criteria fixed **before** results, plus the user's scope decision: Laya only, with Whisper and local LLMs not run.
- Pinned environment: laya 0.3.22, torch 2.14.1, transformers 5.18.0. It lives outside the backend lockfile; the core app gains no dependency.

## Result

**Laya is rejected** against the pre-registered criteria (`docs/experiments/CC-14-laya.md`):

- Alone, it makes 43–75 unsafe downgrades per set.
- In the 0002 hybrid it adds no recall but 17–22 false dangers per 24–30 calls.
- It is fast enough (p95 241 ms on CPU) but poorly calibrated (ECE 0.23).

No adapter is wired, and the core app gains no dependency. Whisper and local LLMs were not run, by the user's decision.

Evidence: `evals/laya/results-multilingual-cpu.json` (per-case predictions for all three modes).

## Handoff

None. This completes the optional task. A future attempt would need fine-tuning and a new pre-registered evaluation.
