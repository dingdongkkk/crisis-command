Notable behaviour:

- Golden test: folding `world.before.json` (seq 52) with events 53–60 reproduces the CC-01 `state_snapshot` example exactly; 53–67 ends with `plan_0007` `dispatched_simulated`.
- Receipts are keyed `(expected_session_id, method, path, key)`; reset receipts use a database-wide scope, so a retried reset returns the same new session even after later resets. Domain rejections are receipted; `IDEMPOTENCY_KEY_REUSED` and `DATABASE_BUSY` are not.
- Reset cancels the old session's pending simulated dispatches (`SimulatedDispatchCancelled{reason: SESSION_RESET}`) in the same transaction that starts the new session.
- Unit status: unavailable or releasing statuses clear the task, list it in `invalidates_assignment_ids`, and bump `desired_revision` (fences stale outbox commands for CC-08). Task-bound statuses without a task → `409 INVALID_TRANSITION`.
- Flood versions must increase by exactly 1 per `flood_id`.
