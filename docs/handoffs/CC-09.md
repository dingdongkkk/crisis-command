## Delivered

- `frontend/src/api/liveApi.ts`: `LiveConsoleApi` over the real HTTP API and `/ws/events` (decision 0005).
  - The server is authoritative: the browser never folds events into state.
  - Events apply only as `last + 1` within one session. Duplicates are ignored.
  - A gap, a new session or `snapshot_required` resyncs from `GET /state` and resubscribes after the snapshot sequence.
  - Event batches trigger one debounced snapshot refresh. `affects_planning` → computing until a plan outcome.
  - 30 s silence → disconnected, then reconnect with 1/2/4/8 s backoff.
  - Commands send `Idempotency-Key`. Problems come back typed, `Retry-After` is surfaced, and network failure becomes `NETWORK_ERROR`.
  - Types are the generated contracts.
- `?mock=` keeps the contract-mock scenarios; without it `main.tsx` uses the live client. The Vite dev and preview servers proxy `/api` (HTTP and WebSocket) to `CRISIS_BACKEND_URL` (default `http://127.0.0.1:8000`).
- Scenario controls (`/demo/advance` T+0 → T+10, `/demo/reset` with confirmation) and a **Simulated call** dialog (`POST /reports`, EN/HI/Hinglish text, a fixed list of demo places). Both are live-only and disabled unless the console is live.
- The reinforcements-by-road panel is restored on the integrated stack using the generated `RouteCandidates` type (`GET /routing/candidates`).
- **Fixed: approval race** (`App.tsx`).
  - Before: the approve dialog rendered whichever proposal was current. If a new version arrived while the operator was reading v4, the dialog silently became v5, and **Confirm** would approve a plan the operator never reviewed. The server rejects this when v5 needs acknowledgements, but not when it needs none.
  - Now: the dialog is bound to the plan id and version it was opened for. Any change replaces it with "Plan changed — nothing approved", which has no approve control.
- **Fixed: dropped live map updates** (`MapView.tsx`).
  - Before: overlay sources were only updated when `map.isStyleLoaded()` was true, and MapLibre reports false while any base tile is loading. A live update during tile loading was lost, so a dispatched plan kept drawing its routes as "Proposed · not dispatched".
  - Now: existing sources are updated directly.
- Flags name what they refer to: incident kind and id, need type, reserve zone and resource. They are shown in the plan panel, the acknowledgement text and the approval summary. The server's `message` is a bare code ("ALS UNMET"), so ten acknowledgements were indistinguishable.
- Top-bar labels no longer wrap at 1440 px.
- `frontend/scripts/e2e-live.mjs`: a live end-to-end run in headless Chrome over CDP against real servers. It writes screenshots and `e2e-results.json`.

## Known limitations

- **Model failure end to end is not demonstrable yet.** Live `POST /reports` constructs `IntakeSession` without a model (`backend/app/api/operations.py`, `report_decision`), so the live path is rules-only (`/health`: `llm_provider: template`). A model outage therefore cannot affect it. Adapter timeouts, transport errors, invalid output and injection are covered by the CC-06 unit tests and triage evaluation.
  - Wiring the adapter needs extraction to run **before** the event-store write transaction: `report_decision` runs under the write lock, and a model call there would block every writer for up to the timeout.
  - It also needs model status surfaced in `/health.degraded`.
  - This is proposed to Codex as a boundary change and was not made here.
- Follow-up questions and answers (`/reports/{id}/answers`) and persisted intake sessions are not implemented; the console displays only what `POST /reports` stored.
- The E2E uses `Network.emulateNetworkConditions` for the disconnect. It does not exercise a backend restart.
