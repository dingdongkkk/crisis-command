Behaviour worth reviewing:

- Approve uses `aria-disabled`, not `disabled`, so `a` can focus it and screen readers announce *why* it is blocked (`… — 5 flags need acknowledgement`, `plan is stale`, `console is not live`). Activation while blocked does nothing (tested).
- Proposed plans always read `PROPOSED vN — not dispatched`; only server state `dispatched_simulated` produces `DISPATCHED (simulated)`.
- Stale approval: no approval applied, notice with the new version, focus moves to the plan header, acknowledgements reset for the new plan version.
- `DATABASE_BUSY` is retried with the **same** idempotency key (tested); every operator decision gets a fresh key.
- Unknown enum values render `Unrecognised (…)` and block approval.
- Triage lists applicable unknown critical facts first under "Not established — treated as present for planning", tags PROVISIONAL / CONFLICT, shows model coercions, and shows evidence as report/char offsets only (no caller text in state).
- Selected incident survives live updates (tested).
- Narrow (< 900 px): tabs plus a sticky plan-status bar with "Review plan".

## Known limitations

- Replay mode and the event timeline from 0006 are not built (CC-04's acceptance list does not include them; they need the live event feed — CC-09).
- Intake conversation screens (question / answer flow) belong to CC-06/CC-09; the triage panel shows recorded facts only.
- Override kinds `downgrade_need` and `revoke` are not in the dialog yet.
- Mock scenarios contain canned outcomes (e.g. the conflict for pinning a locked unit); the browser holds no allocation or policy rules.
- Map tiles need network access to tile.openstreetmap.org; offline, the map shows features plus a "tiles unavailable" notice. Bundle is ~490 kB because AJV and the schema are included for runtime validation.
- Most incidents in the CC-01 checkpoint fixture are named `fixture incident`; CC-10's scenario runner will produce descriptive kinds.
